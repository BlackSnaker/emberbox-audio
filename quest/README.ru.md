# Ember · Quest

[English](README.md) · **Русский**

Ранний WebXR-порт для Meta Quest 3S. Настоящая объёмная комната в Quest Browser,
физический пульт и взаимодействие лучом/щипком. Устанавливаемая версия собирается как подписанный immersive PWA APK через официальный Meta Bubblewrap. Это ранний порт с компаньоном, а не полная автономная замена настольной Ember.

## Два режима

| Возможность | Без ПК | С компаньоном Ember на Linux |
| --- | --- | --- |
| Объёмная комната, 4 темы, физические клавиши и лампы | Да | Да |
| Файл, выбранный на устройстве | Да, если формат поддержан браузером | Да |
| Apple Music / Spotify / Яндекс / YouTube | Отдельные автономные подключения ещё не реализованы | Используются уже подключённые источники ПК |
| Управление треками, громкость, источник, очередь, избранное | Локальный режим ограничен | Реальные команды настольному плееру |
| Коллекция, поиск, релизы и артисты | Нет сервисного каталога | Через адаптеры настольного плеера |
| DJ по текстовому пожеланию | Нет | Обработка на ПК |
| Текст песни | Нет подключения к каталогу | Через существующий клиент слов |
| Караоке и приглушение вокала | Нет | Слова, переключение AI/стерео и интенсивность. Модель предварительно устанавливается в Ember на ПК |
| Голос с микрофона шлема и редактор мешапов в XR | Пока не перенесены | Отдельная XR-адаптация ещё нужна |
| Прямое воспроизведение Atmos / Hi-Res | Не подтверждено | Передача в Quest — **стерео PCM float32, 48 кГц**, без заявления о прямом Atmos/Hi-Res |
| Полноценный MR/passthrough внутри приложения | Пока не реализован | Пока не реализован |

Авторизация сервисов остаётся в Ember на ПК. Пароли, cookies и DRM-ключи в
Quest не передаются. Компаньон включается отдельно, слушает только 127.0.0.1
и требует секрет сопряжения. USB-туннель создаётся через ADB reverse. Секрет хранится приватно в каталоге текущего сеанса ОС. На шлеме сопряжение сохраняется в хранилище приложения; его можно удалить в настройках кнопкой «Забыть сопряжение». Не публикуйте парную ссылку.

Захват звука начинается только после явного нажатия «Звук Ember с ПК».
Используется отдельный PipeWire tap **выбранного приложения**, а не системный
монитор. PCM хранится в ограниченной очереди в памяти; запись на диск не ведётся.

## Запуск с компьютера

Нужны работающая установленная Ember на Linux, Node.js/npm и USB-отладка Quest.
Компаньон перезапускает интерфейс плеера, сохраняя отдельный нативный аудиодвижок.
Текущий сценарий проверяется на установленной GTK-версии; требуется совместимый
каркас `WidgetControl` и `MusicService`. При несовпадении скрипт откажется менять
старую установку. Резервная копия приватна.

```bash
python3 tools/quest.py install-companion
python3 tools/quest.py open
```

Для установленного APK:

```bash
python3 tools/quest.py install-app --apk /path/to/Ember-Quest-0.1.0.apk
# Следующие запуски/повторное сопряжение:
python3 tools/quest.py open-app
```

В браузерной версии в шлеме нажмите **«Войти в комнату»**. Для передачи звука нажмите отдельную кнопку.
Вход в WebXR требует пользовательского жеста; скрипт не обходит разрешения браузера.
Пока используется USB: беспроводное подключение по LAN не включено.

Для APK нужен публичный HTTPS-адрес статической комнаты и Digital Asset Links с SHA-256 **публичного сертификата** пакета. Код упаковки: [`android/generate.cjs`](android/generate.cjs). Пароли и ключ подписи в репозиторий не попадают. Приложение использует установленный Quest Browser как runtime, но запускается из собственной иконки в библиотеке. Для размещённой комнаты компаньон принимает CORS только от явно заданного `EMBERBOX_QUEST_ORIGIN`; токен по-прежнему обязателен. Разрешение браузера на локальную сеть, если появится, выдаётся пользователем.

```bash
npm --prefix quest/android ci --ignore-scripts
npm --prefix quest/android run generate -- https://your-app.example/ /absolute/build/folder
# Далее: JDK 17, Android SDK 32, ./gradlew assembleRelease и подпись своим ключом.
```

Комната и локальные файлы рассчитаны на работу без ПК после первоначальной загрузки ресурсов. Автономный запуск и восстановление офлайн-кэша требуют отдельной проверки на Quest; стриминговые подключения без ПК ещё не реализованы.

ADB берётся из системы либо скачивается с официального сервера Google в кэш
пользователя. Никакие параметры безопасности Quest Browser не отключаются.

```bash
python3 tools/quest.py disable
```

## Разработка и проверка

```bash
npm --prefix quest ci --ignore-scripts
npm --prefix quest run build
npm --prefix quest test
python3 tests/test_quest_bridge.py
```

Для несопряжённого настольного предпросмотра: `npm --prefix quest run dev`.
Измерения `fps`, `drawCalls`, `triangles` формируются в комнате и отправляются
только своему локальному компаньону. Значение FPS оконного режима не считается
подтверждением частоты иммерсивной сессии. Цель 90 Гц запрашивается, если это
разрешает XR runtime; реальные частота, читаемость и работа рук требуют проверки
на шлеме. Устройство без WebXR показывает только предпросмотр.

Графика использует инстансинг, статическое окружение отражений и кэш текстовых
панелей. Полноэкранное размытие, динамические зеркальные камеры и постоянная
генерация картинок обложки в кадровом цикле не используются.

Основа: [Meta WebXR](https://developers.meta.com/vr/documentation/web/webxr-overview/),
[Three.js](https://threejs.org/docs/),
[Android platform-tools](https://developer.android.com/tools/releases/platform-tools).

## Проверено и что осталось

На Quest 3S подтверждён вход в настоящий VR, каталог Apple Music и передача звука с ПК. Предыдущая аппаратная проверка показала 90 FPS, 44 draw calls и 17 628 треугольников. После добавления архитектуры комнаты и новых контролов показатели нужно измерить заново; старый результат не является замером новой сборки.

Новые интерфейсные функции проверяются автоматическими тестами: ограниченный PCM-буфер и восстановление после underrun, пагинация, строки метаданных, громкость, сопряжение, CORS и команды. Перед публичным стабильным релизом остаются проверка APK в шлеме, читаемость и длительное прослушивание.
