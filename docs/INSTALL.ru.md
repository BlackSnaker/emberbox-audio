# Установка Emberbox Audio

[English](INSTALL.md) · **Русский**

## Начать слушать

Нужен современный Linux с PipeWire и **X11 либо Wayland с XWayland**. Запускай установщик от обычного пользователя:

```sh
git clone https://github.com/BlackSnaker/emberbox-audio.git
cd emberbox-audio
./install.sh --autostart
```

Открой **Emberbox Audio** в меню приложений. Без `--autostart` плеер запускается по желанию. Установка не включает музыку сама.

Установщик проверяет имеющиеся компоненты, показывает недостающие и устанавливает их через пакетный менеджер дистрибутива. **`sudo` используется только для недостающих системных пакетов**, с обычным подтверждением пакетного менеджера. Перед подтверждением можно посмотреть команды и список пакетов. `--yes` явно разрешает автоматически принимать эти подтверждения.

Терминал оформлен в палитре [Грунесфизма](DESIGN.ru.md): тёплые янтарные заголовки, понятные шаги и отметки состояния. Сокращённый пример:

```text
  E M B E R B O X   A U D I O
  Немного тепла. С первого шага.
  ────────────────────────────────────────────────
  1/5  Проверка системы
    ✓  GTK 3
    ↓  FFmpeg
  2/5  Подготовка недостающих компонентов
    $ sudo apt-get install --no-install-recommends ffmpeg
  3/5  Установка плеера
  4/5  Интеграция с рабочим столом
  5/5  Можно включать музыку
    ✓  Установлено. Устраивайся поудобнее.
```

Отсутствующий DRM-движок отмечается отдельно: успешная установка приложения ещё не означает подключение всех музыкальных сервисов.

## Какие компоненты готовятся

| Компонент | Для чего нужен |
| --- | --- |
| Python 3.10+, PyGObject, GTK 3, GdkX11 и поддержка SVG | Интерфейс, обложки и интеграция с рабочим столом |
| NumPy, Pillow и websocket-client | Анализ звука, обложки и подключение источников |
| Утилиты PipeWire и `pactl` | Живые лампы и громкость приложения |
| XWayland в сеансе Wayland | Настольный виджет и встроенное воспроизведение |
| libmpv, python-mpv, yt-dlp с совместимыми скриптами EJS | Поиск и воспроизведение YouTube внутри плеера |
| Deno ≥ 2.3 либо Node ≥ 22 | JavaScript-проверки YouTube |
| FFmpeg | Обработка медиа и видеообложки Apple Music |

Совместимые установленные компоненты используются повторно. Недостающие Python-модули устанавливаются только в **управляемое Emberbox виртуальное окружение с `--system-site-packages`**, которому доступны системные привязки GTK. Установщик не запускает `sudo pip` и не меняет системные Python-пакеты через pip. Если подходящего JavaScript-движка нет, в это окружение может быть установлен Deno.

Установщик не устанавливает Spotify, не переключает аудиосерверы, не включает заменяющие их службы, не меняет тему и не добавляет сторонние системные репозитории. Если нужен Spotify, установи официальный клиент отдельно: определяются обычный исполняемый файл `spotify` и Flatpak `com.spotify.Client`.

### Поддерживаемые дистрибутивы

Автоматическая установка недостающих пакетов поддерживает **Arch и совместимые производные, Debian/Ubuntu, Fedora и openSUSE** через `pacman`, `apt-get`, `dnf` и `zypper`. Наличие пакетов зависит от версии дистрибутива и подключённых репозиториев. Если нужный компонент недоступен или неисправен, установка останавливается с диагностикой.

На неизвестных и неизменяемых системах Emberbox не обходит принятый способ установки программ. Сначала предоставь зависимости штатными средствами дистрибутива либо используй готовый пакет, затем запусти `./install.sh --no-deps`. Установка продолжится только после успешной проверки.

## Полезные параметры

| Команда | Что делает |
| --- | --- |
| `./install.sh --check` | Проверка и план установки без изменений: пакеты и файлы приложения не устанавливаются. Если есть недостающие компоненты, возвращается ненулевой код. |
| `./install.sh --no-deps` | Проверяет имеющиеся зависимости и устанавливает приложение; если чего-то не хватает, останавливается. |
| `./install.sh --yes` | Явно принимает подтверждения пакетного менеджера; `sudo` всё ещё может запросить пароль. |
| `./install.sh --autostart` | Включает запуск при входе на рабочий стол. |
| `./install.sh --no-autostart` | Отключает запуск при входе. Обновление без этих двух параметров сохраняет прежнюю настройку. |
| `./install.sh --desktop-shortcut` | Создаёт исполняемый ярлык в папке рабочего стола. Для отображения значков в GNOME нужно соответствующее расширение. |
| `./install.sh --no-desktop-shortcut` | Удаляет управляемый ярлык рабочего стола. Обновление без этих параметров сохраняет его. |
| `./install.sh --no-systemd` | Использует прямой запуск вместо пользовательской службы. Если менеджер служб недоступен, этот вариант выбирается автоматически. |
| `./install.sh --lang ru` / `--lang en` | Выбирает язык установщика; обычно он определяется по локали. |
| `./install.sh --plain` | Простой вывод без цвета; `NO_COLOR=1` также отключает цвета. |
| `./install.sh --skip-check` | Только для сборщиков пакетов: пропускает установку и проверку зависимостей. Приложение не заработает, если пакет не предоставит необходимые компоненты. |

Примеры:

```sh
./install.sh --check --lang ru --plain
./install.sh --no-systemd --autostart
```

## KDE Plasma и GNOME

Виджет использует подсказки оконному менеджеру X11, в том числе через XWayland в сеансе Wayland. Исходное проверенное окружение — **GNOME 50, Wayland + XWayland**. **KWin 6.7.5** дополнительно проверен во вложенном сеансе Wayland с XWayland; полноценный сеанс Plasma Shell этим не проверяется.

В KWin проверены прозрачные скругления на итоговом изображении, положение под приложениями, настоящие события мыши и клавиатуры, перетаскивание за обложку, размещение виджета на всех рабочих столах, фокус полного экрана и возврат по Esc. [Границы проверки, режимы размещения и диагностика KDE](KDE.ru.md).

Запуск из меню и автозапуск XDG получают параметры экрана текущего сеанса рабочего стола. Это позволяет запускаться в KDE без предположений о переменных GNOME. Запускатель умеет использовать пользовательскую службу systemd или запускать процесс напрямую.

Тестерам Plasma предлагаем проверить:

- Из меню и при входе появляется один виджет.
- Перетаскивание, сохранение позиции, мини-режим и меню источников работают при выбранном масштабе экрана.
- Виджет находится под обычными окнами, возвращается по команде **«Показать рабочий стол»** и нормально ведёт себя на виртуальных рабочих столах.
- Полноэкранный режим открывается на нужном мониторе, а **Esc** возвращает настольный виджет.
- Работают встроенное воспроизведение, перемотка, громкость приложения и реакция ламп на звук.
- Сон, повторный вход и смена монитора не оставляют невидимый или второй виджет.

В отчёте укажи дистрибутив, версию Plasma/KWin, тип сеанса X11/Wayland, масштаб и проблемный шаг. Размещение окна и поведение команды **«Показать рабочий стол»** зависят от композитора.

## Аккаунты и DRM

**Настройки → Аккаунты** подключают Spotify, Apple Music и Яндекс Музыку. Вход и платная подписка остаются необходимыми там, где их требует сервис.

Для встроенного воспроизведения Apple Music / Яндекс Музыки Emberbox ищет установленные совместимые компоненты. Когда они найдены, при первичной настройке выполняется ограниченная изолированная проверка AAC/EME. Она проверяет движок, а не подписку или воспроизведение полного трека на стороне сервиса. Отсутствующие или несовместимые DRM-компоненты отмечаются как ограничение с инструкциями по настройке. Установщик не скачивает незаметно непроверенный DRM-движок и не копирует чужой сеанс входа.

YouTube обычно работает без аккаунта; отдельные видео всё ещё могут зависеть от ограничений доступа и изменений сайта. Настоящее воспроизведение Яндекс Музыки с подпиской пока экспериментальное и ожидает проверки тестерами.

## Файлы, обновление и удаление

Кнопка **−** в шапке скрывает виджет, сохраняя воспроизведение; **×** закрывает плеер. В мини-режиме эти действия доступны в Настройках. Нажатие на иконку приложения или ярлык возвращает скрытый плеер без запуска второй копии. В контекстном меню ярлыка также есть «Показать», «Скрыть» и «Закрыть». После закрытия служба не перезапускает плеер; следующее нажатие на ярлык открывает его заново.

Файлы приложения находятся в `$XDG_DATA_HOME/emberbox-audio` (по умолчанию `~/.local/share/emberbox-audio`). Настройки и кеш — в `$XDG_CONFIG_HOME/emberbox-audio` и `$XDG_CACHE_HOME/emberbox-audio`. Установщик отказывается перезаписывать каталог чужой установки. Команда запуска по умолчанию — `~/.local/bin/emberbox-audio`.

```sh
# Остановка при использовании пользовательской службы:
systemctl --user stop emberbox-audio.service
# Обновление после получения свежих исходников:
./install.sh
# Удаление приложения:
./uninstall.sh
```

Удаляются файлы приложения и запускатели, включая управляемое Python-окружение. Личные настройки и кеш сохраняются, как и системные пакеты, установленные пакетным менеджером дистрибутива.

Для запуска из исходников используй `./run.sh`, когда зависимости уже установлены. `GDK_BACKEND=x11` выбран намеренно; сам сеанс Wayland остаётся включённым.

## Если что-то не работает

- **Установка остановилась:** выполни `./install.sh --check --plain` и приложи вывод вместе с ошибкой. Если приложение уже установлено, укажи и команду, завершившуюся ошибкой.
- **Нет окна:** запускай из графического сеанса, проверь XWayland и выполни `~/.local/bin/emberbox-audio` в терминале.
- **Виджет под приложениями:** это нормальное поведение настольного виджета; вернись на рабочий стол.
- **Лампы неподвижны:** проверь, что PipeWire работает и аудиопорты выбранного приложения видны в `pw-link -l`.
- **Нет звука:** проверь тумблер, крутилку и системный микшер приложений.
- **Журнал пользовательской службы:** `journalctl --user -u emberbox-audio.service -n 40`.
